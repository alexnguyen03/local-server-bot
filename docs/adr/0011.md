# ADR-0011: Not using Jenkins yet

Status: Accepted (2026-10)

## Context

Considered Jenkins to replace the orchestration layer (polling, builds, queueing, authorization, history).

## Decision

Not yet. With a handful of services and few users, the scripts plus the bot already cover most of it and are running in production. Jenkins would add a Java service to maintain on LS (around 1 GB of RAM or more) and the orchestration would need rewriting anyway; `deploy-core.sh` would still be needed to call Dockhand.

## Consequences

- Revisit this when a web UI for the whole team, long-term build history, or fine-grained RBAC becomes necessary.
- If trying it: run it alongside, migrate one service as a test, keep the bot for the rest.
- A lighter alternative: a `/last` command that reads `deploy.log`.

## Alternatives considered or deferred

- Jenkins right now; Dockhand's git integration/webhook (its feature set couldn't be confirmed from the docs).
