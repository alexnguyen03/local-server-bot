# ADR-0008: Optional health check and rollback

Status: Accepted (2026-10)

## Context

Some services don't have a health URL yet; we still need to know when a deploy breaks something.

## Decision

If `HEALTH_URL` is set, check it and roll back to the last good build on failure (`ROLLBACK_HEALTH_TIMEOUT=60`). If `HEALTH_URL` is empty, skip the check and say so clearly ("skipping health").

## Consequences

- When it's empty, "OK" only means Dockhand accepted the request. We've seen a stack stuck at `created` with no container still report OK.
- A `wait_running` check against `/api/containers` has been proposed but not implemented yet (backlog item 6).

## Alternatives considered or deferred

- Requiring a health URL: leaves the choice of skipping it up to the user instead.
