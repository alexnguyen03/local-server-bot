# ADR-0007: CS keeps 2 images, LS keeps none

Status: Accepted (2026-10)

## Context

Need to be able to restore quickly, but disk on CS is limited; don't want images kept in two places.

## Decision

The CS registry keeps the newest build and the one right before it (`.prev`). LS keeps no images (docker rmi + prune after pushing; Jib never creates a local image). `cleanup_old` deletes everything else.

## Consequences

- Deletes only take effect with `REGISTRY_STORAGE_DELETE_ENABLED=true`, and disk space is only actually reclaimed after a manual `registry garbage-collect`.
- Restoring is only possible back to the one immediately prior build.

## Alternatives considered or deferred

- Keeping only 1 build: no way to restore if the new one is broken.
- Keeping several builds on LS too: wastes disk.
