# ADR-0006: Flow 2: build on LS when GitHub Actions quota runs out

Status: Accepted (2026-10)

## Context

The org hit the GitHub Actions limit; every workflow (including notify) stopped running. LS has internet and enough capacity to build.

## Decision

`BUILD_MODE=local` in `service.env`. `build-local` polls `git ls-remote`, tags the build `sha-<7>`, does a clean checkout of that exact sha, builds, and pushes straight to CS (bypassing GHCR entirely). `jib` for Quarkus/Gradle (no Docker needed), `docker` for a repo with a Dockerfile (docker build, then skopeo copy to CS). A build failure is remembered by sha and retries are blocked for `BUILD_RETRY_MIN` minutes unless forced with `/redeploy`. Builds run under a `timeout` (`BUILD_TIMEOUT`).

## Consequences

- Removes the dependency on GitHub quota. Also removes the mirror step entirely.
- No test gate (tests don't run as part of the build). Accepted for now.
- Jib pushing over HTTP needs `sendCredentialsOverHttp=true` (hit `RegistryCredentialsNotSentException` without it).
- The first build is slow while dependencies download (the Gradle cache warms up).
- Switching back to flow 1 just means removing the `BUILD_MODE` line.

## Alternatives considered or deferred

- Running a self-hosted runner on a Mac Studio.
- Waiting for the quota to reset.
