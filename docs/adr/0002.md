# ADR-0002: Telegram bot using long polling and fixed scripts

Status: Accepted (2026-10)

## Context

People and CI both need to trigger deploys remotely without opening a port into LS (LS sits behind NAT/VPN).

## Decision

`bot.py` uses python-telegram-bot with long polling. Each Telegram command maps to exactly one fixed string in the `JOBS` table, and the bot only ever calls `deploy-bot` with that string. `deploy-bot` checks it against a regex and only allows entries listed in `/devops/bot.allow`. The user can never supply an argument, a path, or a shell command.

## Consequences

- No public webhook needed.
- Adding a service means adding one line each to `JOBS`, `bot.allow`, and `TREE`.
- Flaky networks need handling (a watchdog, short timeouts, ADR-0009).
- Authorization is a flat list of user ids, not per-command yet.

## Alternatives considered or deferred

- A webhook: needs a public port.
- Letting users type free-form commands: injection risk.
