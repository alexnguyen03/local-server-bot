# ADR-0009: Bot runs as a systemd service, starts with the machine

Status: Accepted (2026-10), updated: LS no longer has to be WSL

## Context

LS can reboot (e.g. a power cut) with nobody around to log in. A dropped network connection also hangs the bot.

## Decision

The `deploy-bot` service (systemd) runs on any Linux machine, WSL2 included. `net_watchdog` exits the process after 15 minutes without a Telegram connection so systemd restarts it. The bot sends "Bot online" once it's up.

Only WSL2 needs an extra Windows Scheduled Task (AtStartup, S4U) to bring WSL up before anyone logs in. That part is split out into [ops/wsl/](../../ops/wsl/).

## Consequences

- Plain Linux needs no Scheduled Task and no keeping WSL alive, making it the recommended choice.
- WSL2: whether S4U actually works after a real reboot hasn't been confirmed; the cause of a 03:27 network failure is unconfirmed (suspected sleep or a dropped network card); Windows sleep and NIC power saving need to be disabled.
- The code itself has no WSL dependency. Only `ops/install-service.sh` has a WSL-specific branch (to enable systemd).

## Alternatives considered or deferred

- Running the bot by hand in a terminal: dies when the window closes or the machine reboots.
