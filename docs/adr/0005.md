# ADR-0005: A 120-second auto-poll as a safety net

Status: Accepted (2026-10)

## Context

The `notify` job can fail to run (quota exhausted, a missing secret), and people forget to trigger a deploy by hand.

## Decision

Every `AUTO_INTERVAL` seconds, the bot runs the jobs listed in `AUTO_DEPLOY`. `deploy` skips itself automatically when the image and compose are unchanged. `/auto_off` and `/auto_on` control it. A bot restart turns it back on automatically.

## Consequences

- On flow local, the auto-poll is actually what triggers a build when HEAD changes (up to ~120 seconds of delay).
- A manual restore to an old tag gets overwritten by the next auto-poll cycle unless you run `/auto_off` first.
- A build failure is remembered for 30 minutes so it doesn't keep retrying.

## Alternatives considered or deferred

- Relying only on CI's notify: commands get lost whenever CI is broken.
- Polling faster: costs more resources for little benefit.
