# ADR-0004: Deploy via the Dockhand API with compose pulled from git

Status: Accepted (2026-10)

## Context

The stack runs under Dockhand on CS. The image tag needs to be updated without SSHing into CS (CS has no public SSH).

## Decision

`deploy-core.sh` fetches the compose file from a repo (`COMPOSE_REPO/PATH/REF`), swaps in the new image tag, then calls `PUT /api/stacks/{name}/compose?env=<id>` with `restart:true`. A `pull_policy: never` line in compose is stripped automatically, since it leaves the stack stuck in `created` with no container.

## Consequences

- The API is asynchronous (returns a `jobId`, with no known result endpoint), so success has to be confirmed with a health check.
- Stack environment variables (DB passwords, `VUE_APP_*`) live in Dockhand; missing one means the container never comes up (this has happened for real).
- Needs a GitHub token with Contents: read.

## Alternatives considered or deferred

- SSH into CS and run `docker compose`: not allowed.
